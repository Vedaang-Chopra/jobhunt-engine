# Existing Project Migration Rules

## Scope
These rules apply retroactively to everything already collected. Do not leave the old project messy and build a parallel structure beside it.

## Audit recursively
Inspect Markdown, CSV/JSON, JDs, company folders, LinkedIn/referral data, application records, agents/sub-agents, skills, scripts, browser/MCP instructions, duplicates, stale files, archives, and root clutter.

## Classify each meaningful item
- canonical/current
- useful but needs merging
- duplicate
- stale
- obsolete
- archive-only
- unknown

## Migration sequence
1. understand existing structure;
2. identify canonical information;
3. design the smallest clean target structure;
4. merge duplicated knowledge;
5. move structured data into canonical datasets;
6. preserve provenance;
7. update README/AGENTS;
8. archive superseded material;
9. delete only clearly redundant material after consolidation;
10. validate references and workflows.

## Markdown cleanup
Merge scattered rules into the canonical modular rule files. Do not keep conflicting versions.

## Data cleanup
Deduplicate jobs, people, companies, hiring posts, and URLs while retaining source history.

## Validation
After migration, verify the directory tree, required canonical files, no useful data loss, one sample company workflow, one multi-source job search, and correct storage destinations.

## Final report
List created, modified, merged, archived, deleted files; unresolved conflicts; canonical tree; skills/workers created; and validation performed.
