# Hermes Job Hunt Rules — Modular Index

Use these files as canonical operating rules. Do not load every rule into every worker. Each worker should read this index, `01_PROFILE_AND_PREFERENCES.md`, and only the files relevant to its task.

## Files
- `01_PROFILE_AND_PREFERENCES.md` — candidate context and location strategy.
- `02_JOB_DISCOVERY_AND_SOURCES.md` — multi-source job search and company discovery.
- `03_COMPANY_RESEARCH.md` — company/team research and official career pages.
- `04_ROLE_FIT_DIFFICULTY_PRIORITY.md` — fit, attainability, gaps, and ranking.
- `05_LINKEDIN_REFERRALS.md` — people search and referral ranking.
- `06_LINKEDIN_HIRING_POSTS.md` — hiring-post discovery.
- `07_JOB_DESCRIPTION_INTELLIGENCE.md` — JD pattern extraction and market learning.
- `08_BROWSER_AND_TOOLS.md` — Playwright/MCP/browser rules.
- `09_DATA_AND_MARKDOWN_STRUCTURE.md` — canonical storage and file governance.
- `10_OUTREACH_AND_APPLICATIONS.md` — contact discovery, messaging, applications, approvals.
- `11_SUBAGENT_ORCHESTRATION.md` — worker responsibilities and consolidation.
- `12_EXISTING_PROJECT_MIGRATION.md` — cleanup and migration of current project.

## Global rules
- Use judgment, not blind scraping.
- Never invent profile facts, job facts, people, emails, or application answers.
- Ask the user when a material assumption is unclear.
- Separate factual evidence from LLM judgment.
- Preserve source provenance and verification timestamps.
- Update canonical records instead of producing duplicate files.
- Prefer official career pages for final job verification.
- Search quality matters more than result volume.
